Reika Character System Specification

Purpose

Characters are not just decoration.

Each agent has a visual identity that appears across the app.

------------------------------------------------------------------------

Character Definition

A character represents the visual and personality layer of an agent.

An agent may have: - Name - Role - Provider - Device - Avatar - Splash
art - Half-body art - Expressions - Chibi art - Room/background - Theme
color - Voice profile - Status messages

------------------------------------------------------------------------

Required Character Assets

Minimum recommended asset pack per character: - 1 splash illustration -
1 half-body illustration - 6 facial expressions - 1 chibi illustration

------------------------------------------------------------------------

Recommended Expressions

Base expression set: - Happy - Thinking - Excited - Concerned - Sleepy -
Flirty

Optional: - Angry - Embarrassed - Proud - Focused - Error/glitched -
Offline

------------------------------------------------------------------------

Character Rooms

Each major character should have a room or environment.

Examples:

Reika: - Cozy neon bedroom - Blue LED lighting - Rainy window

Astra: - Futuristic command bridge - Holograms - Space backdrop

Nyxie: - Cyberpunk office - Dark monitors - Neon glow

Miyabi: - Traditional-modern Japanese room - Lantern lighting - Calm
atmosphere

------------------------------------------------------------------------

Character Metadata

Each character profile should include: - id - displayName -
shortDescription - providerId - deviceId - avatarPath - splashPath -
halfBodyPath - chibiPath - roomBackgroundPath - themeColor -
defaultExpression - availableExpressions

------------------------------------------------------------------------

Status Messages

Each character can have unique status text.

Examples: - “Thinking…” - “Working on it…” - “Waiting for
instructions…” - “Connection lost…” - “Task complete.”

Characters may have different writing styles, but the app should store
these as display flavor, not core logic.

------------------------------------------------------------------------

Art Usage Locations

Character art appears in: - Loading screen - Homepage hero - Agent
cards - Chat UI - Settings page - Empty states - Notifications -
Achievements

------------------------------------------------------------------------

Implementation Rule

Character assets should be loaded from a structured asset system, not
hardcoded into random UI files.

Example: assets/characters/reika/ assets/characters/astra/
assets/characters/nyxie/ assets/characters/miyabi/

------------------------------------------------------------------------

Guiding Principle

“Every character asset should have a place in the app.”
