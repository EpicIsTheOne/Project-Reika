Reika Base Architecture

Core Principle

Reika is NOT an agent.

Reika is a client that connects to agents running on various
providers across various devices.

------------------------------------------------------------------------

Hierarchy

Account └── Devices └── Providers └── Agents

Example:

Epic Account ├── Epic PC │ ├── Hermes │ │ └── Reika │ └── OpenClaw │ └──
Local Assistant └── Hostinger VPS ├── OpenClaw │ ├── Astra │ └── Miyabi
└── Hermes └── Nyxie

------------------------------------------------------------------------

Definitions

Device: - Physical or virtual machine - PC - VPS - Server - Laptop

Provider: - Agent runtime/service - Hermes - OpenClaw - Future providers

Agent: - Individual AI personality/system

------------------------------------------------------------------------

Data Models

Device: - id - name - type - status - providers

Provider: - id - name - deviceId - status - agents

Agent: - id - name - providerId - deviceId - avatar - status

------------------------------------------------------------------------

Communication Model

Reika ↓ Provider Adapter Layer ↓ Provider APIs ↓ Agents

Examples: - Hermes Adapter - OpenClaw Adapter - Future Adapters

------------------------------------------------------------------------

Development Strategy

Phase 1: - Mock devices - Mock providers - Mock agents

Phase 2: - Connect one real provider

Phase 3: - Add networking

Phase 4: - Add advanced features

------------------------------------------------------------------------

Important Rule

Never build all providers simultaneously.

Always: 1. Mock first 2. Build UI 3. Connect one provider 4. Expand
slowly
